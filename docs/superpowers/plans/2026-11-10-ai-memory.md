# AI Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build and test the supplied lightweight conversation archive → NotebookLM → MCP workflow, with a runnable offline demo and honest live-test reporting.

**Architecture:** Reuse audited hstry collectors and extension; Python owns SQLite, Markdown packaging, persistent sync and MCP using notebooklm-py. A single notebook has 49 active segments and a spare slot.

**Tech Stack:** Python 3.12+, SQLite, Node 24+, notebooklm-py, mcp, pytest, uv.

**Spec:** docs/specification.mn.md and docs/superpowers/specs/2026-11-10-ai-memory-design.md.

## Global Constraints

- Preserve source text 1:1; do not summarize, translate or infer missing metadata.
- Only NotebookLM supplies AI memory; no vector database, local LLM or dashboard.
- User-facing thinking/progress only; exclude tool outputs, hidden reasoning and system prompts.
- 49 active sources + 1 spare; target 150,000 words; merge ceiling 450,000 words.
- Google uploads require conversation consent; secret detection blocks cloud sync.
- Work in the existing isolated checkout; do not create a worktree. Do not publish or push.

## Review Focus

- Parser whitespace changes, multipart text, and mirrored Codex events: prove exact text and no duplicates.
- Edited/deleted messages and out-of-order continuations: preserve identities and invalidate the right sources.
- Crash after upload or before deletion: retain the old source until readiness and reconcile without duplicate uploads.
- Full notebook or exhausted maximum segment size: fail without deleting data or inventing summaries.
- Auth absence, credentials in source text, browser-origin requests and citation uncertainty: report the true state and never fabricate successful retrieval.
